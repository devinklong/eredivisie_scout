# Patch List

Fixes to things that were built, ran, and behaved wrong — not a build plan. See `v1_roadmap.md` for what's still unbuilt.

## Open

1. **WhoScored `read_events()` reliability** — has crashed on 3 separate runs now (2026-08-27 morning, 2026-08-27 afternoon, 2026-08-28), always the same `_is_captcha_present()` TypeError on `None` page_source, always self-heals on retry within the same script run. **Likely real cause, per user (2026-08-28): closing/minimizing the automated Chrome tab mid-run.** SeleniumBase's UC mode pops up a real visible browser window during each `read_events()` call — if that tab gets closed or loses focus while the script is still working, the driver loses its window handle, which matches the `window_handles[-1]` IndexError seen once and is consistent with the browser-session-death pattern behind the other two crashes. Not a soccerdata bug — a workflow habit to fix: leave the SeleniumBase-launched Chrome window alone (don't close/minimize it) until the script finishes. Revisit only if it still happens after consistently not touching the window.

2. **Historical season coverage mapped (2026-09-01) — fallback parser built but NOT yet integrated into the batch scraper.** Confirmed via full-season runs and targeted diagnostics across 2010-11 through 2025-26:
   - **2020-21 through 2025-26: work cleanly with the standard `scrape_all_whoscored_matches.py` path.** No issues.
   - **2019-20: deliberately lighter, NOT a bug.** 197/250 matches succeeded — the season was suspended 12 March 2020 and formally annulled by the KNVB on 24 April 2020 due to COVID-19, after each club had played ~25 of 34 scheduled matches. The 53 "missing" matches never happened in real life — no champion, no promotion/relegation that year either. Confirmed via external search.
   - **2015-16 through 2018-19: real event data exists on WhoScored, but soccerdata's standard `read_events()` path crashes on it** (`TypeError: cannot safely cast non-equivalent object to int64`). Root-caused to soccerdata's internal `.astype("Int64")` step choking on how these older seasons' events represent `related_event_id` (frequently `None`, inconsistently typed). Confirmed the real data exists and is usable via `output_fmt="raw"`, which bypasses soccerdata's formatting entirely — `tests/whoscored/parse_raw_whoscored_events.py` is a working converter (real events, real player/team names via a corrected cache-path lookup) built and tested against a real 2015-16 match (1,412 events recovered). **NOT yet wired into `scrape_all_whoscored_matches.py` as a fallback — that integration is the concrete next step**, and would let 2015-16 through 2018-19 (and likely earlier seasons) actually be scraped rather than lost to the casting bug.
   - **2010-11 through 2014-15: at least partially, likely mostly, genuinely empty on WhoScored's own side — not yet fully confirmed.** One specific 2010-11 match (`game_id=409048`) was confirmed via `output_fmt="raw"` to have zero events — WhoScored's own log says `"No events found for game 409048"`, and the raw JSON itself is empty, not just soccerdata's formatting failing. This is a genuine data absence, not a parsing bug — but only one match has been directly checked this way; the full extent across 2010-11 through 2014-15 is inferred, not exhaustively confirmed.

## Done

- FBref access via `soccerdata` + SeleniumBase UC mode (Cloudflare bypass) — confirmed working, `standard`/`shooting`/`misc`/`playing_time`/`keeper` categories return real data.
- WhoScored access confirmed working for NED-Eredivisie via soccerdata (required a custom `WhoScored` entry in `league_dict.json`, same file as the FBref entry). `read_schedule()` and `read_events()` both tested successfully against real matches.
- **`derive_possession_stats.py` penalty-area mislabeling (2026-08-28)** — script originally computed only one penalty-area zone (x ≤ 17, near the defensive goal line) but labeled it `touches_att_pen_area`. Caught via a goalkeeper sanity check: Stijn van Gassel had by far the most touches in that zone (33), which only makes sense for a defensive box. Fixed by splitting into both `touches_def_pen_area` and `touches_att_pen_area`, computed from opposite ends of the pitch (x≤17 vs x≥83). Re-ran and confirmed: keeper now correctly shows 33 in `touches_def_pen_area`, 0 in `touches_att_pen_area`.
- **Calendar refetch inefficiency, root-caused and fixed, CONFIRMED (2026-08-31).** Root cause: `read_events()` unconditionally calls `self.read_schedule(force_cache)` internally on every call, and `read_schedule()`'s caching logic (`no_cache = current_season and not force_cache`) deliberately skips the local cache for an in-progress season unless `force_cache=True` is passed — found by reading soccerdata's actual source (`whoscored.py`). **Fix confirmed via `tests/whoscored/test_whoscored_instance_reuse.py`, re-run with `force_cache=True` on both `read_schedule()` and `read_events()`:** `read_schedule` dropped from 137.0s to 0.2s; the three `read_events()` calls dropped from 129.0s/147.9s/228.6s to 0.1-0.2s each — roughly a 1000x speedup, reproduced identically across two consecutive runs. WhoScored season-scale batch scraping (~300+ matches) is now genuinely fast, not the 10-20+ hour job the unfixed version would have been. Tradeoff still applies: `force_cache=True` won't pick up newly-added fixtures/results — fine for historical batch work, do a `force_cache=False` refresh when current-season data needs to be up to date.
